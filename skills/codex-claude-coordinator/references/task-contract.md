# Claude 实现任务契约

每次委派实现或修复任务时使用以下结构。

```markdown
# 任务

## 目标
描述一个具体的实现结果。

## 仓库背景
说明相关架构、入口、约定和现有行为。要求 Claude 编辑前先检查实际代码。

## 范围
- Claude 可以修改的文件或组件。
- Claude 必须新增或更新的代码和测试。

## 非目标
- 明确排除的行为和重构。

## Claude Code 工作流
- OMC 主工作流：填写 `autopilot`、`ralph`、`team`、`ultrawork` 或 `ultraqa`；不得同时填写多个。
- 准确调用：填写完整的 `/oh-my-claudecode:...` 调用及参数。
- 辅助行为：按需填写 `tdd`、`code-review`、`security-review` 或 `visual-verdict`。
- 选择原因：说明为什么适合本任务。
- 并发与隔离：说明单写入者、独立 worktree 或只读并行方案。
- 不可用时：停止并报告阻塞，不得模拟 OMC 或静默切换模式。

## 执行边界
- 最大子代理数：默认 10；按任务风险调整，但不得省略。
- 最大修复轮数：默认 3；`ralph` 同样受此限制。
- 并发写入：默认单写入者；使用多代理时列出独立 worktree 或其他隔离证据。
- 状态阶段：按“调研 → 规划 → 实现 → 验证 → 交付”汇报可观察进展，不汇报隐藏思维链。
- 达到边界：停止并在“阻塞问题”中说明，不得自行扩大范围或无限重试。

## 验收标准
1. 可观察、可测试的标准。
2. 可观察、可测试的标准。

## 必须执行的验证
- 准确列出测试、检查、构建或格式化命令。

## 约束
- 保留工作树中已有的无关改动。
- 不要提交、推送、重置、变基或切换分支。
- 不要泄露、生成或修改密钥。
- 不要仅为让测试通过而削弱测试。
- 遇到阻塞时应报告问题，不要擅自改变需求。
- 只允许一个 OMC 主循环控制者；不得启动相互竞争的循环。
- 不得删除或篡改 `.codex/claude-coordinator/` 中的运行状态。
```

修复任务还应添加 `## 失败证据`，包含准确的失败命令和简明输出。
